# Frontend references

- Use when design knowledge, examples or implementation guidance would improve the result.
- Project-specific references define the direction. This library supports judgment.
- Choose the relevant source below; follow WORKFLOW.md for lookup steps.
- Use free reference content only; skip paywalls, paid exports and trials requiring payment. No MCP setup is needed.
- Judge individual examples against TASTE.md. Inclusion does not endorse every design on a site.
- Visual sources inform craft. UX research informs behavior. Standards inform requirements.
- Select examples for composition, typography, identity and interaction craft. Gallery inclusion, awards and sponsored placement do not establish UX quality.

## Product styling and extracted design context

- [Refero Styles](https://styles.refero.design/) — product-site style references. Find a relevant product; compare its typography, spacing, color and component treatment with the original rendered site.
- [designmd.supply](https://designmd.supply/) — browse public generated style guides by domain; compare useful tokens and descriptions against the original site.
- [Google DESIGN.md specification](https://github.com/google-labs-code/design.md) — consult when reading or producing that format. It is optional; keep the target's existing design system and conventions.
- Treat extracted tokens and descriptions as secondary evidence. Verify important values and behavior; do not import entire style files or another product's identity by default.

## Typography and color

- [Fonts In Use](https://fontsinuse.com/) — type in real compositions. Find relevant uses; inspect hierarchy, pairing, spacing and identity.
- [Google Fonts Knowledge](https://fonts.google.com/knowledge) — type selection, variable fonts, readability and language support. Search the specific typography question.
- [WebAIM Contrast Checker](https://webaim.org/resources/contrastchecker/) — check actual foreground/background combinations.
- [Material color guidance](https://m3.material.io/styles/color/overview) — semantic color roles and themes when a system needs structure; retain the project's visual identity.

## UX, navigation and conversion

- [Nielsen Norman Group](https://www.nngroup.com/articles/) — usability, navigation, hierarchy and interaction. Search the specific task or pattern; read evidence and context.
- [NN/g information architecture](https://www.nngroup.com/topic/information-architecture/) — grouping, hierarchy and findability; [navigation](https://www.nngroup.com/topic/navigation/) — menus, wayfinding and search. Start with the relevant topic when the problem is structural.
- [Laws of UX](https://lawsofux.com/) — explanations of attention, cognitive load and decision behavior. Use relevant principles to examine a specific interaction; check context and evidence before treating a heuristic as a rule.
- [Baymard free research](https://baymard.com/free-ux-research) — product pages, search, filtering, forms and checkout. Use findings for matching commerce tasks; do not generalize them into universal landing-page formulas.
- Baymard topic shortcuts: [product pages](https://baymard.com/blog/collections/product-page), [cart/checkout](https://baymard.com/blog/collections/cart-and-checkout), [search](https://baymard.com/blog/collections/on-site-search), [lists/filtering](https://baymard.com/blog/collections/product-list). Read the relevant public finding and its examples.
- [NN/g writing for the web](https://www.nngroup.com/topic/writing-web/) — clear labels, scannable content and comprehension. Apply to real product copy and intended actions.

## Components, forms and working applications

- [The Component Gallery](https://component.gallery/) — compare component behaviors and states. Find the component, then open the original design-system documentation.
- [Atlassian Design System](https://atlassian.design/) — dense application patterns, navigation and feedback. Borrow interaction logic, not its brand styling.
- [Shopify Polaris](https://polaris.shopify.com/) — commerce administration, resource lists and product language. Inspect matching patterns when building merchant-facing workflows.
- [GOV.UK Design System patterns](https://design-system.service.gov.uk/patterns/) — forms, validation, confirmation and task completion. Read the matching pattern and accessibility guidance; use as behavioral evidence, not a visual target.
- [WAI-ARIA APG](https://www.w3.org/WAI/ARIA/apg/) — widget semantics, keyboard behavior and focus. Find the exact pattern; favor native controls where suitable.

## Reusable frontend implementation

- Reuse the target's components and installed libraries first. Choose resources for the actual stack and task; this is not a mandatory stack.
- Reuse tested behavior and mechanics; tailor composition, typography, content and styling to the project. Build custom parts where existing options do not fit.
- Check current APIs, compatibility, license and relevant states before adoption. Add only needed code/dependencies in the target, never in this kit.

### React components and accessible primitives

- [shadcn/ui](https://ui.shadcn.com/docs/components) — free editable component source and blocks. Inspect the relevant example and dependencies; adapt its styling and content.
- [Base UI](https://base-ui.com/) — unstyled React primitives for bespoke interfaces, including overlays and selection controls. Use its composed behavior while designing your own appearance.
- [React Aria](https://react-aria.adobe.com/) — accessible interactions, collections, dates and internationalization with custom styles. Useful for complex app controls and diverse input methods.
- [Radix Primitives](https://www.radix-ui.com/primitives) — accessible, unstyled controls; especially useful when already established in the target. Preserve its behavior when restyling.
- [Mantine](https://mantine.dev/) — broader React component coverage and hooks when a working application benefits from a cohesive library. Adapt its theme to the accepted direction.

### Application mechanics

- [TanStack](https://tanstack.com/) — Table for table logic, Virtual for large collections, Query for remote-state handling and Form for form state. Use the relevant package and framework adapter, not the entire stack.
- [React Hook Form](https://react-hook-form.com/) — React form state and validation integration when it fits the target; retain clear labels, errors and recovery.
- [Floating UI](https://floating-ui.com/) — robust anchored positioning for custom popovers/tooltips. Prefer a complete existing primitive when it already solves the interaction.
- [Lucide](https://lucide.dev/) — consistent SVG icons across frameworks; reuse the existing icon family when present.
- [Apache ECharts](https://echarts.apache.org/) — interactive charts when a dashboard needs mature chart mechanics; apply Datawrapper guidance to the information design.

### Motion and 3D

- [Motion](https://motion.dev/docs) — React, JavaScript and Vue animation, layout transitions, gestures and scroll effects. Use the free library; premium examples/tools are separate.
- [GSAP](https://gsap.com/docs/v3/) — timelines and coordinated scroll animation across stacks. Use for choreography that benefits from it; preserve natural scrolling and reduced motion.
- [React Three Fiber](https://r3f.docs.pmnd.rs/getting-started/introduction) — composable Three.js scenes in React; match supported React/Fiber versions.
- [Drei](https://github.com/pmndrs/drei) — reusable Fiber helpers for controls, text, environments and loading. Inspect the relevant helper before writing its mechanics yourself.
- Use the Three.js documentation/examples below for renderer-specific work. Keep simple DOM effects in CSS when that achieves the intended result.

## Accessibility and responsive implementation

- [WCAG](https://www.w3.org/WAI/standards-guidelines/wcag/) — applicable accessibility requirements. Read the relevant criterion and supporting guidance.
- [WebAIM resources](https://webaim.org/resources/) — practical accessibility testing and implementation.
- [MDN](https://developer.mozilla.org/) — semantic HTML, CSS, browser APIs and compatibility. Check the actual feature before implementing unfamiliar behavior.
- [web.dev Web Vitals](https://web.dev/articles/vitals) — loading, responsiveness and layout stability. Use measurements to investigate experienced performance.

## Specialized interface needs

- [Datawrapper guidance](https://www.datawrapper.de/blog/category/datavis-dos-and-donts) — dashboard chart choice, labels, comparisons and meaningful color. Find the relevant chart or communication problem.
- [Datawrapper Academy](https://www.datawrapper.de/academy) — practical chart, map and table examples; use when implementation or presentation needs more detail.
- [Microsoft HAX Toolkit](https://www.microsoft.com/en-us/haxtoolkit/) — AI interface feedback, control and recovery. Use matching interaction guidelines.
- [Google People + AI Guidebook](https://pair.withgoogle.com/guidebook-v2/) — AI expectations, uncertainty and failure states. Read the chapter for the actual UX problem.
- [FIDO passkey design guidelines](https://www.passkeycentral.org/design-guidelines/) — passkey creation, sign-in and recovery communication when authentication UI is in scope.
- [W3C Internationalization](https://www.w3.org/International/) — text expansion, language and bidirectional behavior when required by the project.
- [Three.js examples](https://threejs.org/examples/) — technical reference when a chosen design needs 3D/WebGL. Inspect the matching example's code; a technical demo is not an art-direction target.
- [Spline examples](https://spline.design/examples) — interactive 3D compositions when relevant to the interface. Inspect interaction and embedding requirements before adopting a scene.
- [Design Tokens format](https://www.designtokens.org/TR/2025.10/format/) — token interchange when the project needs it. No requirement to introduce a token toolchain.
