IMPLEMENTATION IS A SEPARATE USER-SELECTED TASK
Updated: October 8, 2026.

Design Kit iterates through IMAGES of text treatments, icons, components,
component groups, sections or whole pages. For broad designs, the default
begins with a first representative component IMAGE and builds a visually
consistent IMAGE-BASED COMPONENT LIBRARY before optional section images.

The user or Design Kit can refine each component's visual images. After
EVERY image round or returned batch, ask the user whether to revise, accept,
advance or stop. The user may stop at any milestone.

Inside each requested visual unit, PHASED_REFINEMENT.md can guide concept,
craft, optional advanced depth and user/context review. Its first phase means
generating a visual concept image, NOT implementing working software.
The last phase is a visual review, NOT permission for auto-conversion.

Image-based component specimens are not implemented UI elements, editable
Figma components or validated design tokens. No transition to final design,
component coding, Figma creation or image-to-code conversion is automatic.

If the user asks for a handoff, report selected images/versions, foundation
status, actual inspected MCP reference relationships, exact source copy
where available, user decisions and relevant unverified visual limits.
Never claim static generated images establish working UI behavior.

Legacy SOFTWARE.md, QA.md and PRODUCT_DELIVERY.md are retained for a
SEPARATE USER-SELECTED TASK outside Design Kit's image-generation scope.
