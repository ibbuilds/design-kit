IMPROVE EXISTING VISUAL DESIGN — ANY SCALE
Updated: October 8, 2026.

Accept an existing image of text, icon, component, family, section, screen or
whole design. Keep its protected choices and actual content. Do not demand
rebuilding the entire library for a local correction or impose sections first.

Inspect the actual current image, selected earlier exemplars, confirmed or
provisional foundation and relevant real MCP/user reference imagery.
Form a material revision: KEEP accepted relationships, REWORK the visible
weakness, and state the EXPECTED difference. Generate new IMAGE concepts,
compare at the same scope and preserve stronger earlier versions.

AFTER EVERY IMAGE ROUND OR RETURNED BATCH show the result and ASK whether to
revise, accept, try a different direction, generate related components, move
to another unit or stop. Honor unlimited user-led rounds within real budgets.

For library-wide work, choose the strongest accepted component image as the
style anchor. Refine inconsistent sibling component images, singly or in
GROUPS when shared styling is stable. The user can refine the library, and
Design Kit can propose and regenerate visual improvements. Sections inherit
the approved component styles only when the user asks for them.

Use existing Awwwards / One Page Love MCPs to resolve concrete visual gaps;
reuse relevant inspected sources instead of researching each component afresh.
A whole-page image may be revised directly. Stop at the user's own milestone.
Image concepts are not working components or final editable design.
