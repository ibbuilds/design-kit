# Artifact-first revision: rationale and validation

Review date: October 6, 2026. Base: `9930439875d9b25446056ffbefb12df263ea29ec`.
Maintainer-only record; not part of normal design context or the installed package.

## What is being changed

Replace the default supervised itinerary with one bounded, rendered design assignment. Keep optional supervision, protected identity, source fidelity, complaint-led craft, canonical repairs, real responsive/state inspection and accepted-code reuse. Remove compulsory intermediate approval sequences, initial reference minimums, automatic complementary discovery and system-specimen-before-screen ordering from the active flow.

The intended quality mechanism is not brevity alone. The entrypoint makes a concrete visual gap/opportunity, coherent intervention, in-context authoring and comparison to a relevant quality anchor the center of the assignment. Existing craft knowledge stays available selectively. A materially weaker candidate must not be propagated merely because tests pass.

One candidate / two refinement passes and one discovery query / one fallback are proposed spending defaults, not experimentally optimal counts. Explicit user budgets and reserved decisions override them. The kit does not technically enforce model quota or visual judgment.

No new service, agent runtime, model split, vector store, UI library or MCP is introduced. Existing installer/configuration/compatibility helpers and selected provider declarations are preserved. Those declarations do not demonstrate a live connection or eliminate host-specific setup behavior. The task procedure does not call setup or both providers by routine.

## Validation boundaries

Existing package/configuration tests must remain intact. New instruction-contract lint checks active routing, bounded execution and removal of known contradictory phrases. These are structural regression checks, not tests of agent obedience, taste, interactions or savings. The full package suite and its result must be reported separately from any local subset.

No target application, real model comparison, paid endpoint or user's installed configuration is changed by this maintenance revision. `REFERENCES.md`, blank `BRIEF.md`, detailed CRAFT.md and installer/provider scripts remain unchanged. Historical research/evaluation documents preserve older supervised decisions; they do not override the active SKILL.md or certify this revision.

## Smallest useful output test

Use one necessary screen/family in the real product, with a recoverable starting revision. First confirm the intended installed skill revision is active. Hold model/effort, content, viewport, source access and an explicit budget constant. Compare a no-kit run with the revised-kit run only when the user allocates that test budget; never launch this automatically during maintenance.

Judge the rendered pair without the agent's promotional rationale: requested visible quality, preserved valued treatments, coherence in context, required behavior/responsive states, human intervention and observable total usage. Use anonymous A/B labels when practical. Reuse a prior baseline only when its conditions are genuinely comparable; otherwise call it illustrative, not controlled.

A before/after improvement proves only that the artifact improved. A matched with/without-kit comparison is preliminary evidence about the kit; it does not establish repeatability. If there is no meaningful visual advantage at comparable effort, record that result and do not promote the revision as a quality boost. Repeated real-task acceptance is stronger evidence than adding more instructions.
