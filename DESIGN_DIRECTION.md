# Visual judgment from one element to an entire page

Under [SKILL.md](SKILL.md), critique **the actual generated image**, not a persuasive explanation. Judge at the scope the user asked for: a text treatment needs legible type; a control needs deliberate proportions and weight; a group needs family consistency; a section needs composition; a page needs pacing.

## Where the style authority comes from

Early on, inspect user images and relevant real Awwwards/One Page Love MCP examples. Design Kit may propose foundation choices, clearly labelled. Once a **first component exemplar image is selected**, reuse its typography, geometry, density, color roles and material language across related components. When the visual component library is consistent, **reuse its actual images** to anchor sections. Don't restart the same styling question for every sibling or infer exact token values from one generated image.

## Material revisions by scope

| Visible issue | Useful image change |
| --- | --- |
| Text looks generic or unreadable | Rework hierarchy, letterform character, wrap, contrast and line rhythm |
| Button or input looks weak | Change proportion, label hierarchy, material/edge and relationship to sibling controls |
| Component family drifts | Generate corrected specimens with accepted exemplar and shared style relationships |
| Whole library feels consistently ordinary | Reopen the foundational treatment rather than micro-polishing every unit |
| Section looks disconnected | Recompose around chosen components, focal point and content purpose |
| Page feels repetitive | Adjust section pacing and variety without replacing accepted component language |

A **substantial change** means an observable improvement in visual structure or treatment, not a large number of arbitrary edits. Minor polish is useful after the main style is established. Compare new images with the strongest retained versions at equivalent content and scale.

When the user is refining a component library, show selected component images together and identify outliers. The user **or Design Kit** can revise these images. After **every generated image iteration or batch**, ask what to do next; don't equate an agent selection with approval.

Use [REFERENCE_ROUTER.md](REFERENCE_ROUTER.md) for actual inspected source relationships, but a gallery still can't verify interactions, accessibility or CSS values. Stop when the user chooses—element, component, library, section or page. Final editable design/implementation is separate.
