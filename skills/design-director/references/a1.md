# Optional A1 MCP research

Verified 2026-09-04 against [A1 MCP](https://www.a1.gallery/mcp),
[A1's Codex setup](https://www.a1.gallery/mcp/codex) and
[official Codex MCP documentation](https://developers.openai.com/codex/mcp).
These document capabilities, not proof that a particular account exposes them.

Reliable Figma read/write/current-render access is core to native design execution. A1 is an optional research
accelerator. It has no required dependency entry, bundled connection or automatic
installation in Design Kit. Absence must never block ordinary design work.

## Detect and degrade gracefully

Only when reference research materially helps the current request, inspect the
current host's available tool inventory (or tool discovery if provided) for the A1
connection and read its actual schemas. A server name alone is not proof of a
working tool; `codex mcp list` confirms configuration, not authentication or health.
Tool prefixes may vary: identify provider provenance, not a hardcoded namespace.
Do not call a documented tool name until the host exposes its callable schema.

When present and source policy allows, use a relevant bounded read/search as the
health check and useful work together. If missing, unauthenticated, rate-limited,
timed out or unsupported, continue with available browser/reference tools under
the SAME source policy. Retain already acquired material. Briefly report a limit
only if it affects the answer; do not turn setup into a prerequisite or repeatedly
retry an unavailable optional service. Never claim metadata or images were inspected
without successful evidence. No silent install, login, upgrade or purchase.

## Source authority before tool choice

Follow [visual-reference policy](visual-references.md): current instructions and
task/project references first, then preferences and permitted retained library;
discover only coverage gaps through the allowed pool.
A1 is a transport/catalogue capability, not permission to widen the pool or a
source of canonical taste. Sufficient user references need no A1 supplementation.

If the user restricts research to certain galleries, do not use A1's broader corpus
as a substitute. Use it only if its actual schema can restrict the query to the
permitted material with verifiable provenance; otherwise skip it. A style/category
filter is not a source restriction. Filtering unrestricted results afterward does
not authorize the original search. A1's docs currently establish no arbitrary
gallery-origin filter; do not assume one exists. Never follow outgoing site links
or retrieve outside captures merely because A1 returned them. Respect an explicit
no-external-reference/no-defaults/no-reference request, including for aggregate queries.

## Useful capabilities, not a call sequence

Current official documentation lists these examples; inspect current schemas and
use only the subset that answers the unresolved design question:

| Need | Documented A1 capabilities |
|---|---|
| Relevant sites and comparable directions | `search_websites`, `browse_websites`, `get_similar_websites`, `get_website` |
| Captured sections/pages and their context | `search_sections`, `get_website_sections`, `search_pages`, `get_website_pages` |
| Fonts and creators | `browse_fonts`, `get_font`, `find_font_pairings`, `browse_creators`, `get_creator` |
| Supported facets or measured values | `get_design_filters`, `analyze_design_tokens`, `analyze_section_content` |

Inspect query broadening and dropped filters reported by the provider. Label looser
matches; source exclusions still apply and may require discarding a broadened result.
Prefer supplied captures with source attribution over replacement screenshots.
Open selected captures visually; structured fonts, colours, spacing, radius, layout,
copy and categories supplement pixel inspection. Measurements may describe one
capture, viewport or extraction; they do not establish responsive behavior, usability,
accessibility, licensing or the right solution for this task. Aggregate quartiles
are corpus observations, never universal design tokens or a default visual style.
Persist valid captures discovered within permitted sources even when they are not
selected for today's task. Reuse retained captures before querying again. Do not
request the whole catalogue or indiscriminately scrape sections. Apply the shared
[research policy](visual-references.md): explore broadly when useful, curate a task
working set, and inspect the subset relevant to the current decision. Stop on
relevance saturation, not a small count. Retain images as external runtime material with exact
page/asset provenance through [reference storage](session.md), never bundle them.

## Explicit opt-in setup

Only when the user asks to connect A1, use its documented Codex setup:

```sh
codex mcp add a1 --url https://www.a1.gallery/api/mcp
```

An A1 account and OAuth consent are required. Follow the sign-in flow; if it was
not completed during add, use `codex mcp login a1`. Inspect configured servers first
and preserve an existing connection instead of overwriting it. Do not store tokens
in the plugin or repository. Start a fresh Codex task if the active host has not
refreshed its tools. Confirm tools and a scoped request, not just `mcp list`.

Codex documents HTTP/OAuth connections and an optional `required` server setting.
Leave A1 optional (never set `required = true`). The optional connection lives in
the user's Codex configuration; Design Kit does not manage its lifecycle. A1's plan
limits may change; consult its current documentation when a limit matters.
