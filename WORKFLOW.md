# Design and frontend entrypoints

The canonical procedure is now [SKILL.md](SKILL.md). Read and apply it for frontend work; do not run another sequence from this file.

It conducts or resumes [guided onboarding](ONBOARDING.md) by default, obtains missing phase inputs, and distinguishes no base/moodboard, structural composition, foundations-only, final design and accepted code. [DESIGN_DIRECTION.md](DESIGN_DIRECTION.md) and [TASTE.md](TASTE.md) guide UI/UX quality and comparison with the actual base; [REFERENCE_ROUTER.md](REFERENCE_ROUTER.md) scopes reference research. The agent performs applicable [QA.md](QA.md) checks inside the authorized batch. Review-only requests stop after findings without editing project records.

For requested frontend code, [SOFTWARE.md](SOFTWARE.md) is the canonical implementation workflow; backend work is outside this kit. [PROVIDERS.md](PROVIDERS.md) covers selected reference MCPs and setup. [EXECUTION.md](EXECUTION.md) supplies effort/context guidance while preserving the user's current model. The installer optionally adds an explicit frontend-code pointer with `--with-software`; the design entrypoint already routes requested frontend implementation.

Existing project facts and accepted decisions remain authoritative. A legacy project copy of BRIEF.md can continue to hold its context. See [README.md](README.md) for supported interfaces and user/project installation.
